# Android-to-iOS feature parity

This is the stable cross-platform capability inventory. Android behavior at annotated tag `android-parity-ios-v1` is authoritative; shared contracts and fixtures corroborate it. Preserve IDs and append new IDs rather than renumbering. Implementation order, checkpoint status, and human-review evidence live only in [porting-plan.md](porting-plan.md).

iOS v1 contains **52 in-scope observable capabilities** from F001–F055. F013, F052, and F055 are explicitly **Deferred**, leaving 52 targets. A row becomes **Complete** only after implementation, required final verification/device evidence, empty/error states, accessibility behavior, and human review pass. Full-app testing is deferred until groups A–F are implemented and the user explicitly approves the separate testing gate; feature approval does not authorize it. **Partial** may mean reusable domain/service code exists even when its production UI is absent; **Not started** means no material implementation; **Deferred** is an explicit product decision, not an omitted task. Android also uses **Dormant** and **Unused** for compiled behavior outside its normal shipping flow.

Priority is porting priority (`P0` highest); complexity is relative (`S`, `M`, `L`, `XL`). Behavioral details are in [android-app-analysis.md](android-app-analysis.md), and the execution/acceptance contract is in [porting-plan.md](porting-plan.md).

## Coverage and implementation checkpoint

There are **55 stable IDs**: 13 catalog/library, 11 song/theory, 15 playback/quiz, 10 microphone/vocal-practice, and 6 user-data/maintenance/platform capabilities. Exactly **52 are in iOS v1 scope** and exactly **3 are Deferred** (F013, F052, F055). No web-only capability is included.

The implementation preserves substantial package, catalog, audio, theory, and persistence code and its existing tests. Library/settings/search, Song Detail/Chords, and the initial Quiz timelines/transport are implemented to varying review states; All Songs and Playlist destinations remain placeholders. No iOS row is Complete: feature review and approved final verification are separate stages in [porting-plan.md](porting-plan.md). Android behavior/source references remain in [android-app-analysis.md](android-app-analysis.md); current review evidence belongs only in the canonical plan.
