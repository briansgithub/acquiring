# Android-to-iOS feature parity

This is the stable cross-platform capability inventory. Android behavior at annotated tag `android-parity-ios-v1` is authoritative; shared contracts and fixtures corroborate it. Preserve IDs and append new IDs rather than renumbering. Implementation order, checkpoint status, and human-review evidence live only in [porting-plan.md](porting-plan.md).

iOS v1 contains **52 in-scope observable capabilities** from F001–F055. F013, F052, and F055 are explicitly **Deferred**, leaving 52 targets. A row becomes **Complete** only after its implementation, automated tests, required device evidence, empty/error states, accessibility behavior, and human review pass. **Partial** may mean reusable domain/service code exists even when its production UI is absent; **Not started** means no material implementation; **Deferred** is an explicit product decision, not an omitted task. Android also uses **Dormant** and **Unused** for compiled behavior outside its normal shipping flow.

Priority is porting priority (`P0` highest); complexity is relative (`S`, `M`, `L`, `XL`). Behavioral details are in [android-app-analysis.md](android-app-analysis.md), and the execution/acceptance contract is in [porting-plan.md](porting-plan.md).

## Coverage and implementation checkpoint

There are **55 stable IDs**: 13 catalog/library, 11 song/theory, 15 playback/quiz, 10 microphone/vocal-practice, and 6 user-data/maintenance/platform capabilities. Exactly **52 are in iOS v1 scope** and exactly **3 are Deferred** (F013, F052, F055). No web-only capability is included.

The current checkpoint preserves substantial package, catalog, audio, theory, and persistence code, and `swift test --package-path ios/Packages/AcquiringKit list` enumerates 164 package tests. The post-reset Library and bare Quiz contain limited visible behavior, while All Songs, Playlist, and Song Detail are placeholders. No iOS row is Complete: existing implementation enters the checkpoint review flow in [porting-plan.md](porting-plan.md). Android behavior and source references are documented in [android-app-analysis.md](android-app-analysis.md); iOS review evidence belongs with the canonical plan rather than in that Android audit.
